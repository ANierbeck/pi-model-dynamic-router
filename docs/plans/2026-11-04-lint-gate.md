# Lint Gate Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Status:** in progress (2026-11-04) — Tasks 1-7b done (gate live in CI and the pre-push hook); burn-down slices S1-S4 done (baseline 1217 findings / 299 entries → 955 / 183 → 919 / 159 → 915 → 810 / 130; the 915 re-measure is the Prettier reformat), S5 open, tracked in `TODO.md`

**Problem:** ESLint is installed but never runs. There is no `lint` script, no CI
step, and `eslint.config.js` has never been executed against the tree — the only
mention of linting is an unchecked line in `RELEASE_CHECKLIST.md` ("No linting
errors (`npx eslint src/`)") that cannot be ticked. Run today, the configured
ruleset reports **1224 findings (862 errors) in 65 files**, so the checklist line
is not merely unenforced, it is unsatisfiable. Every finding is invisible to
review, CI and the release process.

**Solution:** Make lint a real gate with a ratcheting baseline, the same shape
this repo already uses for ADR-0025 (`scripts/hardcoded-model-baseline.json`) and
the redundancy report (`scripts/redundancy-baseline.json`): existing findings are
baselined per file and rule, the baseline may only shrink, and new findings fail
the build. Then burn the baseline down in slices.

`package-lock.json`, `@typescript-eslint/*` 8.61.1, Node floor `>=22.19.0`,
Pi host 1.5.0. All numbers below were measured on that commit, not from memory.

Two facts that shape the plan:

1. **`no-console` is a config bug, not 83 code defects.** Every hit is in
   `scripts/` (CLI tools where `console` is the correct output). `src/` has zero
   `console.*` hits — it uses `src/logger.ts`. Scoping the rule correctly
   removes 83 findings without touching code.
2. **`test/` is not in `tsconfig.json`** (`exclude: ["test/**/*.ts"]`), so
   type-aware rules cannot run there. Tests need their own non-type-checked
   block, and `no-explicit-any` must be off there: 1340 of the 1418 test findings
   are `any` in fixtures, which is legitimate.

## Architecture

Three pieces, deliberately split by cost:

1. **`eslint.config.js`** — scoped rulesets: type-checked for
   `src/ index.ts scripts/`, non-type-checked for `test/`.
2. **`scripts/lint-gate.ts`** — runs ESLint programmatically, aggregates findings
   per `(file, rule)`, compares against `scripts/lint-baseline.json`, and exits
   non-zero on a new finding or a stale (fixable-but-not-lowered) entry. Runs as
   `npm run lint`. This is the enforcement; it takes ~5 s.
3. **`test/lint-baseline.test.ts`** — fast, no ESLint run: pins the baseline's
   canonical shape (sorted, unique, positive counts) and a `CEILING` total that
   must move together with the baseline, exactly like
   `test/redundancy-baseline.test.ts`. This keeps the ratchet honest inside the
   suite, which is what CI's required `test` job runs.

Why the split: the suite stays fast, and the ratchet still cannot be loosened
silently, because growing the baseline requires raising `CEILING` in the same
commit — a visible, reviewable line.

**Step 1: Write the script**

```ts
#!/usr/bin/env node
// Lint gate: compares the current ESLint findings against a ratcheting
// baseline (scripts/lint-baseline.json). The baseline may only shrink.
// Modelled on scripts/scan-hardcoded-models.ts (ADR-0025) and
// scripts/redundancy-report.ts.
import { ESLint } from 'eslint';
import { readFileSync, writeFileSync } from 'node:fs';

export interface LintEntry {
  file: string; // repo-relative, POSIX separators
  rule: string;
  count: number;
}

export interface LintBaseline {
  note: string;
  entries: LintEntry[];
}

const BASELINE_PATH = 'scripts/lint-baseline.json';
const TARGETS = ['src', 'index.ts', 'scripts', 'test'];

/** Aggregate ESLint results into canonical (file, rule) counts. */
export function toEntries(results: ESLint.LintResult[], root: string): LintEntry[] {
  const counts = new Map<string, number>();
  for (const result of results) {
    const file = result.filePath.slice(root.length + 1).split('\\').join('/');
    for (const message of result.messages) {
      // `fatal: true` is a parse error; a null ruleId without it is an unused
      // eslint-disable directive. Bucketing both as 'fatal' would let a real
      // parse error hide behind a baselined directive warning.
      const rule = message.fatal ? 'fatal' : (message.ruleId ?? 'eslint-directive');
      const key = `${file}\u0000${rule}`;
      counts.set(key, (counts.get(key) ?? 0) + 1);
    }
  }
  return [...counts.entries()]
    .map(([key, count]) => {
      const [file, rule] = key.split('\u0000');
      return { file, rule, count };
    })
    // UTF-16 code-unit order, matching Array.prototype.sort() in the canonical
    // test; localeCompare orders differently (a_b before a-b).
    .sort((a, b) => (a.file < b.file ? -1 : a.file > b.file ? 1 : a.rule < b.rule ? -1 : a.rule > b.rule ? 1 : 0));
}

/**
 * Two violation kinds, mirroring compareToBaseline in the ADR-0025 guard:
 * a finding above its baseline entry is NEW; a finding below it means the
 * entry is stale and has to be LOWERED in the same change.
 */
export function compareToBaseline(found: LintEntry[], baseline: LintEntry[]): string[] {
  const violations: string[] = [];
  const base = new Map(baseline.map((e) => [`${e.file}\u0000${e.rule}`, e.count]));
  for (const entry of found) {
    const allowed = base.get(`${entry.file}\u0000${entry.rule}`) ?? 0;
    if (entry.count > allowed) {
      violations.push(`NEW ${entry.rule} in ${entry.file}: ${entry.count} (baseline ${allowed})`);
    }
    base.delete(`${entry.file}\u0000${entry.rule}`);
  }
  for (const [key, count] of base) {
    const [file, rule] = key.split('\u0000');
    violations.push(`BASELINE entry is stale and must be LOWERED: ${rule} in ${file} (${count})`);
  }
  return violations;
}

async function main(): Promise<void> {
  const root = process.cwd();
  const write = process.argv.includes('--write');
  const eslint = new ESLint({ cwd: root });
  const results = await eslint.lintFiles(TARGETS);
  const found = toEntries(results, root);
  const total = found.reduce((sum, e) => sum + e.count, 0);

  if (write) {
    const baseline: LintBaseline = {
      note: 'Ratcheting lint baseline (docs/plans/2026-11-04-lint-gate.md). Only shrinks.',
      entries: found,
    };
    writeFileSync(join(root, BASELINE_PATH), `${JSON.stringify(baseline, null, 2)}\n`);
    console.log(`wrote ${BASELINE_PATH}: ${found.length} entries, ${total} findings`);
    return;
  }

  const baseline = JSON.parse(readFileSync(BASELINE_PATH, 'utf8')) as LintBaseline;
  const violations = compareToBaseline(found, baseline.entries);
  if (violations.length > 0) {
    console.error(violations.join('\n'));
    console.error(`\n${violations.length} violation(s). Fix them, or lower ${BASELINE_PATH}.`);
    process.exit(1);
  }
  console.log(`lint gate ok: ${total} findings, all baselined`);
}

if (invokedDirectly(import.meta.url)) {
  await main();
}
```

```ts
// Fast ratchet guard: no ESLint run here (that is `npm run lint`). This pins the
// baseline's shape and a CEILING that must move together with it, exactly like
// test/redundancy-baseline.test.ts. Growing the baseline therefore requires
// editing a visible constant in this file in the same commit.
import { describe, it, expect } from 'vitest';
import { readFileSync } from 'node:fs';
import { join } from 'node:path';

interface LintEntry { file: string; rule: string; count: number }
interface LintBaseline { note: string; entries: LintEntry[] }

const CEILING_FINDINGS = 1217; // <-- set to the measured total in Task 3

const baseline = JSON.parse(
  readFileSync(join(process.cwd(), 'scripts/lint-baseline.json'), 'utf8'),
) as LintBaseline;

describe('lint baseline ratchet', () => {
  it('is canonical: sorted, unique per (file, rule), positive integer counts', () => {
    const keys = baseline.entries.map((e) => `${e.file}\u0000${e.rule}`);
    expect(keys, 'entries must be sorted by file then rule').toEqual([...keys].sort());
    expect(new Set(keys).size, 'no duplicate (file, rule) entries').toBe(keys.length);
    for (const e of baseline.entries) {
      expect(Number.isInteger(e.count) && e.count > 0, `${e.file} ${e.rule}: count ${e.count}`).toBe(true);
    }
  });

  it('stays at or below the ceiling', () => {
    const total = baseline.entries.reduce((sum, e) => sum + e.count, 0);
    expect(total, 'lower the baseline and CEILING_FINDINGS together').toBeLessThanOrEqual(CEILING_FINDINGS);
  });

  it('the ceiling moves with the baseline (no silent headroom)', () => {
    const total = baseline.entries.reduce((sum, e) => sum + e.count, 0);
    expect(total, 'a cleanup lowers the baseline and CEILING_FINDINGS in the same change').toBe(CEILING_FINDINGS);
  });
});
```

## Decisions (owner, 2026-11-04)

**D1 — Ruleset scope: type-checked, fully baselined.** The gate starts from
`flat/recommended-type-checked` with all 1224 findings baselined. Rejected:
dropping the `no-unsafe-*` family (550 findings, but leaves the family
permanently unchecked) and the non-type-checked ruleset (198 findings, gives up
the type-aware rules that justify ESLint here at all).

**D2 — The gate runs as a step in the existing required `test` job.** No new
job, no ruleset change: the `test` job is already required by "Protect main", so
the gate bites on the first PR. Cost ~5 s. A separate `lint` job was rejected
because it would not be enforced until the owner edits the ruleset.

**D3 — `explicit-function-return-type` stays and is burned down in slice S4.**
Explicit return types are treated as an API contract at the Pi boundary, not as
style. Rejected: dropping the rule.

**D4 — Warnings count as findings.** The baseline has no severity column, so
`no-explicit-any: 'warn'` is enforced exactly like an error. Rejected: gating on
errors only — that is how the current unenforced state came about.
