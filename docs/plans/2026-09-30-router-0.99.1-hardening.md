## Goal

Make every router `registerProvider` call safe under Pi 0.99.1's layered model registry, so scans and re-registrations can neither **wipe** pi-known models (chat, image, or classifier) nor **corrupt** them (re-register a non-chat model as chat) — while the same code keeps working on 0.87.1 for rollback safety.

## Research findings (evidence, 0.99.1 tarballs)

Facts verified against `@earendil-works/pi-coding-agent@0.99.1` and `@earendil-works/pi-ai@0.99.1` tarballs (re-packed into `/tmp/pi099-hard/`):

1. **Layered composition replaces flat storage.** `ModelRuntime.composeProvider` (`dist/core/model-runtime.js:166-186`) composes each provider as **builtin catalog + user `models.json` + extension overlay**. `registerProvider` (`model-runtime.js:635-666`) stores the extension overlay, merges top-level fields with the *previous extension registration* (undefined keys preserved), validates **before** mutating (a broken re-registration throws cleanly), then recomposes.
2. **`extension.models` replaces the composed model list wholesale.** `applyExtension` (`dist/core/provider-composer.js:171-178`): if the extension config defines `models`, the composed list is **only** the extension models — the builtin catalog's and models.json's entries are dropped. The `images`/`classifiers` *implementation maps* survive on the composed provider (`provider-composer.js:389-413`), but the **model entries** die → `findOfType("image"/"classifier", …)` returns nothing, the models vanish from `getModelsOfType`.
3. **The builtin catalog ships non-chat inventory under provider ids we re-register.** openrouter: ~500 chat + **53 image models** (flux.2, gemini-*-image, gpt-image-*, …) + **8 classifier models** (`typesafe/jev-1.13`, `~typesafe/jev-latest`, `jaredpalmer/kev-4b`, `respan/span-01*`, `upstage/solar-decide`); there is also a classifier-only `typesafe` provider (`jev-latest`). Non-chat model objects carry fields the chat allow-list drops: `type`, `output` (image), `inputLimits`.
4. **New bug beyond the wipe: our round-trip strips `type`.** The scan-union round-trip (post-`85fcdff`, `index.ts` ~3254-3266) starts from `getAll()` — which under 0.99.1 returns models of **all types** — but the field allow-list has no `type`, `output`, `inputLimits`, or `promptCache`. Result: an image model that survives the union is re-registered **as a chat model** (corrupting the chat list, e.g. `google/gemini-3-pro-image` becoming chat-selectable).
5. **Registration queue.** `registerProvider` calls from an extension's `load()` are queued pre-bind and flushed at `bindCore` (`dist/core/extensions/loader.js:135,163-166`); calls after bind — i.e. from `session_start`, where the router registers — apply immediately (confirmed live: router.log 2026-09-30 09:48:37).
6. **Live status.** No scan has run under 0.99.1: router.log 09:48:32 "Scan cache is still valid (max 30 days old), skipping regeneration". The running dist build is from Sep 29 — it predates `85fcdff`, so a scan today would additionally wipe scan-absent chat models (roborev 649). Hardening + rebuild must land before the next scan; the scan cache (mtime 2026-09-30 11:50) is valid up to 30 days from its `scan_date`.
7. **Other call sites are safe as built:**
   - Group providers (`index.ts:1646`) use router-owned provider ids — no builtin overlap.
   - `registerFreeModelOnDemand` (`index.ts:2335`) only fires when `getRegisteredProviderIds()` does **not** contain the provider (Ü1 invariant) — under 0.99.1 that set includes all builtins, so it degrades to "never overwrite a known provider" (conservative, correct).
   - Ollama registration (`index.ts:3332`) only fires when pi knows none of the scanned local models; ollama has no builtin-catalog entry and no non-chat models.
8. **Recovery lever (new in 0.99.1).** `unregisterProvider(id)` recomposes from builtin + models.json only — a bad extension overlay is reversible in-session, unlike 0.87.1's destructive replace.

## Tasks

### Task 1 — Failing regression test (TDD, red first)

New test file `test/register-union-preserves-non-chat-models.test.ts` (mirrors the `withIsolatedRouter` harness of `test/register-group-models-merge-not-replace.test.ts`):

- Mock `modelRegistry.getAll()` to return for provider `openrouter`: one known chat model, one image model (with `type: "image"`, `api: "openrouter-images"`, `output`, `inputLimits`), one classifier model (`type: "classifier"`, e.g. `typesafe/jev-1.13`).
- Scan reports the known chat model **plus one new chat model** (forces the union path past the skip check).
- Assert the `registerProvider` call's `models` array:
  1. image model present with `type: "image"` intact and `output`/`inputLimits` preserved,
  2. classifier model present with `type: "classifier"` intact,
  3. known chat model preserved (byte-for-byte fields),
  4. scan-new chat model present with chat defaults (`reasoning`/`input` from capabilities).
- Also assert the **skip path**: when the scan reports no new models, no `registerProvider` call happens (non-chat models untouched).
- **RED expectation:** current allow-list strips `type` → image model appears with no `type` (defaults to chat). Prove red before implementing.

### Task 2 — Implementation (scan-union site, `index.ts` ~3254-3266)

- Extend the round-trip allow-list with **conditional spreads** (pattern already used for `api`/`baseUrl`):
  - `...(m.type !== undefined ? { type: m.type } : {})` — preserves image/classifier identity; absent on 0.87.1 chat models → no change there,
  - `...(m.output !== undefined ? { output: m.output } : {})`,
  - `...(m.inputLimits !== undefined ? { inputLimits: m.inputLimits } : {})`,
  - `...(m.promptCache !== undefined ? { promptCache: m.promptCache } : {})`.
- Keep everything else (getAll-based union start, skip check, find()-fallback, cost semantics) unchanged.
- Update the block comment: 0.99.1 layered composition, extension-`models` replace semantics, non-chat preservation, reference ADR-0019 and roborev 649.
- No change to `registerFreeModelOnDemand`, group, or ollama sites (documented safe in finding 7 — add a one-line comment pointing at ADR-0019 where Ü1/`getRegisteredProviderIds` guards exist).
