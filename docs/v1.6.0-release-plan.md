## 2) Enforced Delegation (ADR-0007, Revision 2026-09-20 a+b)

The Spotify Portal/shunt architecture: the expensive model pays for answers,
never for bulk content. Three delivered pieces:

- **Tool-result shrinker** (`src/delegation.ts`): oversized `read` AND `bash`
  results are summarized by the delegation group (default `bulk_reader`) in the
  `tool_result` hook, fail-open everywhere. Threshold-gated (`min_chars` 3500,
  shunt-aligned). Targeted reads and piped/grep'd bash pass through untouched.
  Router narration (`> [router]` lines) is stripped from sub-call output.
- **Read pre-block** (`src/bulk-read.ts`, `checkReadBlock`): a full-file read
  (no offset/limit) of a file above `block_lines` (default 350) is blocked in
  the `tool_call` hook BEFORE execution; the reason redirects to `bulk_read` or
  a targeted read. `block_lines: 0` disables the block, the shrinker keeps
  working. Deliberate divergence from shunt: bash is NOT pre-blocked.
- **`bulk_read` tool** (`executeBulkRead`): question-based multi-file reading —
  files are read from disk, capped, sent to the delegation group; only the
  concise answer returns to the orchestrator.

## 4) Cost resolution: registry-first (effCost fix)

- `getM()` previously zeroed `cost_per_m` for subscription providers BEFORE
  consulting the registry — Mistral subscriptions with real prices ($1.4) read
  as "free" and landed in `max_cost:0` groups.
- `resolveCostPerM(ref)` is the authoritative chain: registry → local →
  subscription → cache → `:free` → `unknown`. Registry BEFORE subscription
  zeroing; SUB_DISCOUNT (0.5) applies only to explicitly subscription-billed
  providers (1.4 → 0.7).
- Healing in `getM()`'s early-return path fires ONLY for placeholders
  (`0` / `'unknown'`) — explicit user prices are never overwritten.
- Commits: `78bb3be` (incl. `bb89756`, `e2bc251` mock-realism prerequisites).
- Tests: metrics-cost-heal.test.ts (11 tests, rewritten non-vacuously).

## 8) Robust cloud classifier fallback + quality probe (offline Ollama)

The classifier's degradation chain (primary Ollama → fallback Ollama →
cloud → static) now works reliably when the local daemon is unavailable,
and cloud candidates are QUALITY-verified instead of reachability-only.

- `isOllamaAvailable()` (`src/ollama-utils.ts`): GET /api/tags with a 1.5s
  cap and a 15s negative cache guards both local attempts; a hanging
  daemon no longer burns primary+fallback timeouts on every prompt.
- Cloud fallback chain in `classifyPrompt` (`src/content-classifier.ts`):
  pinned model (`classifier_cloud_model`) → scan-time probe-verified list
  → tiered discovery → configured free models → static classification.
  Never throws; opt-in via the dynamic-group option
  `classifier_cloud_fallback`. Statically-routed simple prompts (trivial/
simple/code_simple) go straight to the cheap tier without an LLM call.
- Quality probe (`src/classifier-fallback-probe.ts`): three real
  classification cases through the SAME shared prompt surface as the
  runtime classifier (`classification-prompt.ts`), including a
  hint-narration trap (any `hint:*` reply fails — no probe case contains
  a HINT request). Bounded: max 20 candidates, 15s per case, stops at 8
  verified successes. Verified refs are cached in
  `cache.classifier_fallback_models` and reused until the next `/router`
  scan. Rationale: the voxtral-small incident (2026-09-26) — an audio
  model passed a "Reply with OK" reachability probe, then copied the
  `HINT: use group tactical` narration out of the context block instead
  of classifying, misrouting to tactical.
- Runtime spurious-hint guard (`09fa5b6`, code review 2026-09-26,
  Important #1): cloud hint replies share the Ollama path's conversion
  (`toHintClassification`) and are only accepted when the current request
  itself carries a HINT marker (`containsHintMarker`); narrated-HINT
  echoes are skipped to the next candidate. Pinned refs already in the
  probe list move to position 0 (tried-FIRST contract, Minor #3).
- Fixed dead trivial branch: a literal 0x08 control byte in the
  trivialKeywords regex made it unmatchable ("what's in this file?" fell
  through to 'simple' instead of 'trivial'); original design expectation
  (c67b7b4) restored.

Commits: `019a383`, `6444371`, `65998ee`, `09fa5b6`. Tests: 42 chain/
mapping tests + 23 probe tests + 3 review-regression tests.

## 9) Expensive-model Layer-1 escalation (2026-09-26)

**What**: `checkReadBlock` (shunt Layer 1) gains an expensive-model path:
members of expensive groups (default `strategic` + `tactical`, via the
active config's materialized `model_groups.<name>.models` lists) or behind
`delegation.expensive_providers` prefixes get EVERY full-file read blocked
and redirected to `bulk_read`/targeted reads — regardless of file size. The
size threshold (`block_lines`, default 350) keeps protecting all other
models unchanged.

**Why**: (a) every file-read token on a $2/$10 model is pure waste when the
bulk_reader answers for ~$0 — expensive models should orchestrate and
reason (user decision 2026-09-26: "sie könnten sich dann um die teuren dinge
aus der session kümmern"); (b) live evidence 2026-09-26: pi-claude sessions
crash on file tool calls (kendex bridge ENOENT — 4 warnings per session), so
routing file inspection through bulk_read avoids the broken path entirely.

**Key mechanics**:
- `Router.getCurModel(turnStartMs)` — the factual stream ref of the CURRENT
  turn (`setCurModel` timestamps; stale refs from a previous turn return
  `''`), so the block works through dynamic/HINT routing. Fixed sessions fall
  back to the session ref (`expensive_providers` match).
- Fail-open preserved everywhere: unknown model, missing group lists,
  nonexistent files, stat errors, `block_lines: 0`, delegation disabled.
- Targeted reads (offset/limit) are NEVER blocked — edit workflows need
  exact lines.
- Config: `delegation.expensive_groups` (default `["strategic", "tactical"]`),
  `delegation.expensive_providers` (default `[]`); both written into
  router-config.json self-documenting.

**Tests**: `test/expensive-model-read-block.test.ts` — 24 regression tests
(settings validation, group/prefix matching incl. `{ref}` defensive form,
block/pass matrix for expensive vs cheap vs unknown models, stale-guard).
