# Host alignment to pi 1.6.1

**Date:** 2026-11-27 — AGENTS §10 alignment round (installed `pi` CLI 1.6.1,
repo devDependencies were `^1.6.0` / 1.6.0 in `node_modules`).

**Verdict:** no change needed in the extension. Both virtual-model spike gates
match the recorded Pi 1.6.0 baselines.

## What 1.6.1 changes (checked against the 1.6.0 → 1.6.1 `dist/**/*.d.ts` diff and the release notes)

| Area | Change | Touches the router? |
| --- | --- | --- |
| `SettingsManager` | `getShowCacheMissNotices()` / `setShowCacheMissNotices()` removed; `getNotices()` / `setNotice()` added (`notices.cacheMisses`, `.cacheWarming`, `.compactionCosts`, `.reasoningDrops`) | No — `grep` finds neither the removed methods nor the settings key anywhere in `src/`, `index.ts` or the tests |
| `after_provider_response` | Now also fires for HTTP 4xx/5xx and each retried attempt on OpenAI, Azure OpenAI, Anthropic and Google | No — the router does not subscribe to it (only research notes mention it as a possible future observation hook) |
| Retry classification | More transient failures retry automatically: Cloudflare 525, gateway "temporarily unavailable", Anthropic `api_error` mid-stream, OpenRouter empty responses, `finish_reason: "error"`, "request rate increased too quickly" | Indirectly — Pi's own retry layer sits in front of the router's retry matrix; the matrix below still matches the baseline |
| Thinking `off` | Claude Sonnet 5.5 via GitHub Copilot, Opus 5.5 / Sonnet 5.5 via Cloudflare AI Gateway and Vercel AI Gateway now use the lowest supported level instead of failing with HTTP 400 | Relevant to the thinking-level plan only (`docs/plans/2026-11-25-thinking-level-per-group.md`); no code today |
| Catalog | Default Mistral model `devstral-medium-latest` → `mistral-medium-latest`; shut-down models removed (`gpt-5-chat-latest`, three Groq models, `mistral-medium-3.5`) | No — the router derives its pool from Pi's registry (ADR-0021) |
| Extension API | `ctx.ui.select/confirm/input` accept `blockedKind`; `ProviderAuthStatus` documents `{configured:false, source:"stored"}` for a stored `!command` key that fails; `clearConfigValueCacheEntry()`; bash tool `fullOutputError` | No |
| Dev lock | `pi-ai` 1.6.1 declares `@google/genai` 3.6.1 (was 2.32.0) and `@aws-sdk/credential-provider-node` 3.972.82 | Dev lock only — `pi-ai`, `pi-coding-agent`, `pi-tui` stay `--external` in the build, the published tarball has no runtime dependencies |

Not a downgrade anywhere in the lock diff: eight `1.6.0 → 1.6.1` host
packages, `@google/genai` up, one new nested `@aws-sdk` package.
