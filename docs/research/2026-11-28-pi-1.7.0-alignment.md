# Host alignment to pi 1.7.0

**Date:** 2026-11-28. AGENTS §10 alignment round: the installed `pi` CLI is
1.7.0 (published 2026-11-27, npm `latest`), and the devDependencies move from
exactly `1.6.1` to exactly `1.7.0`. Previous round:
`docs/research/2026-11-27-pi-1.6.1-alignment.md`.

## What 1.7.0 changes and whether it reaches the router

Checked against the release notes and a diff of the 1.6.1 and 1.7.0
`dist/**/*.d.ts` of `pi-coding-agent`, `pi-ai` and `pi-agent-core`.

| Change | Reaches the router? |
| --- | --- |
| Telemetry removed (`enableInstallTelemetry`, `SettingsManager.get/setEnableInstallTelemetry`, `PI_TELEMETRY`) | No. The router does not use `SettingsManager`. |
| `--agent-dir <dir>`, the flag form of `PI_CODING_AGENT_DIR` | No change needed. The router resolves the agent dir from `PI_CODING_AGENT_DIR` (`src/agent-dir.ts`), and Pi applies the flag by setting that variable before it loads extensions (`dist/cli/agent-dir-arg.js`, called first in `main.js`). The user layer `router-config.user.json` therefore follows the flag. |
| Terminal session resume (OSC 7577) reopens a session as `pi --session <id>` | No change needed, by code reading. The group restore reads the branch at `session_start` regardless of the start reason (`src/event-handlers.ts`, `restoreVirtualSelection`), so `--session` takes the same path as `--continue`. Not tested live. |
| `!!` commands no longer count toward Pi's context estimate | No. The router estimates on the `Context` Pi hands to the stream call (`src/stream-orchestrator.ts`, `estimateContextTokens`), which Pi builds after dropping excluded messages. |
| Copilot prompt cache kept across thinking-level and tool changes; Copilot Claude supports cache warming | Nothing to do. The router honours Pi's `cacheWarming` generically, without a provider list. |
| Image generation (`KnownImageApi` gains `pi-image`, `aspectRatio`/`size` options, `usage.imageOutput`) | No. `imageOutput` is a subset of `output`, so the router's cost accounting does not double-count it. |
| `compat.supportsReasoningReplay` in the model schema | No. Additive, the router does not read it. |
| `ant-ling` default model changed; `thinkingFormat: "ant-ling"` becomes an alias of `"deepseek"` | No. The provider id `ant-ling` still exists, so `PI_BUILTIN_PROVIDER_IDS` stays. The router does not read `thinkingFormat`. |
| `pi-ai` removes `KnownImageApi` (moved), `getRadiusAllModelsFromConfig`, `PI_AI_VERSION`, `ClassifierHttpError`, `isRecord` from its exports | No. None is imported by `src/`, `index.ts` or `test/`. All 15 symbols the router imports from `pi-ai` are still exported. |

The extension API (`core/extensions/*.d.ts`), `model-registry.d.ts` and
`pi-agent-core` have no `.d.ts` change. `model-runtime.js` and
`model-registry.js` are byte-identical in 1.6.1 and 1.7.0, so the private
`modelRegistry.runtime` reach-throughs (`streamSimple`, `completeSimple`)
are unchanged.

## Lock diff

Only the eight host packages move `1.6.1 → 1.7.0`: `pi-agent-core`, `pi-ai`,
`pi-codemode`, `pi-coding-agent`, `pi-mcp`, `pi-schema`, `pi-telemetry`,
`pi-tui`. No third-party package changes, no downgrade. Dev lock only:
`pi-ai`, `pi-coding-agent` and `pi-tui` stay `--external` in the build.
