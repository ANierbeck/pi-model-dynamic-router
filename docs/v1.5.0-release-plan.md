# v1.5.0 — Combined Release Plan

> Created 2026-08-28. Combines all open threads into one feature/minor release.

## Collected open threads (sources: memory, TODO.md, git log, router.log, conversation)

### Thread A — Ollama Crash Prevention (diagnosed, plan exists)
- **Problem:** 6 Ollama models streamed in parallel within 75ms → ~55 GB RAM
  → Mac OOM crash.
- **Source:** `docs/ollama-crash-prevention-plan.md` (fully diagnosed).
- **Fix:** process-internal semaphore for `ollama`/`lm-studio`, config
  `ollama_max_concurrent_streams` (default 1), soft-fail to the cloud
  fallback when exceeded.
- **Status:** plan settled, decisions taken (soft-fail, default 1).
- **Effort:** ~1 day (config + semaphore + test + docs).

### Thread B — OpenRouter free models not registered ("GLM not used")
- **Problem:** OpenRouter free models (`openrouter/z-ai/glm-5.2:free`,
  `openrouter/cohere/north-mini-code:free`, etc.) appear as candidates in the
  dynamic config, but `tryStream` skips them as "not registered in Pi's model
  registry" → claude-sonnet-5 dominates, free models unused.
- **Evidence:** `~/.pi/logs/router.log` shows hundreds of
  `tryStream skipped "openrouter/.../...:free": not registered` entries.
- **Root cause:** the scan writes free models to
  `cache.available_models` + the dynamic config, but
  `registerGroupProviders` only registers group providers (virtual) and
  `registerGroupModels` only Ollama (when Pi doesn't know it). OpenRouter
  models are **never** registered into Pi's model registry via
  `pi.registerProvider` → `tryStream` doesn't find them.
- **Fix direction:** register scan-discovered OpenRouter models via
  `pi.registerProvider('openrouter', {models: [...]})` (analogous to the
  Ollama registration in `registerGroupModels`), so that
  `modelRegistry.find('openrouter', id)` finds them.
- **Effort:** ~1-2 days (registration + tests + ensuring no double
  registration with other extensions).

### Thread C — claude-sonnet-5 dominance (part of B)
- **Problem:** the user observed exclusive routing to
  `pi-claude/claude-sonnet-5` for days, even for simple tasks.
- **Cause:** when the free models (thread B) are unavailable because they are
  not registered, the cascade always falls to the next available model —
  which is `pi-claude/claude-sonnet-5` (claude-bridge). It's a **symptom of
  B**, not a separate bug.
- **Fix:** resolved with thread B — once free models are registered and
  `tryStream` finds them, the group cascade will use them too.
- **Effort:** 0 (included in B).
