# v1.5.0 — Combined Release Plan

> Created 2026-08-28. Combines all open threads into one feature/minor release.

## Collected open threads (sources: memory, TODO.md, git log, router.log, conversation)

### Thread A — Ollama Crash Prevention (diagnosed, plan exists)
- **Problem:** 6 Ollama-Modelle in 75ms parallel gestreamt → ~55 GB RAM → Mac-OOM-Crash.
- **Source:** `docs/ollama-crash-prevention-plan.md` (fertig diagnostiziert).
- **Fix:** Prozess-interne Semaphore für `ollama`/`lm-studio`, Config `ollama_max_concurrent_streams` (default 1), soft-fail zum Cloud-Fallback bei Überschreitung.
- **Status:** Plan steht, Entscheidungen getroffen (soft-fail, default 1).
- **Aufwand:** ~1 Tag (Config + Semaphore + Test + Doku).

### Thread B — OpenRouter Free-Modelle nicht registriert ("GLM not used")
- **Problem:** OpenRouter-Free-Modelle (`openrouter/z-ai/glm-5.2:free`, `openrouter/cohere/north-mini-code:free`, etc.) erscheinen in der dynamischen Config als Kandidaten, werden beim `tryStream` aber als "not registered in Pi's model registry" übersprungen → claude-sonnet-5 dominiert, Free-Modelle ungenutzt.
- **Beweis:** `~/.pi/logs/router.log` zeigt hunderte `tryStream skipped "openrouter/.../...:free": not registered` Einträge.
- **Root Cause:** Scan schreibt Free-Modelle nach `cache.available_models` + dynamische Config, aber `registerGroupProviders` registriert nur Gruppen-Provider (virtuell) und `registerGroupModels` nur Ollama (wenn Pi es nicht kennt). OpenRouter-Modelle werden **nie** via `pi.registerProvider` in Pi's Model Registry registriert → `tryStream` findet sie nicht.
- **Fix-Richtung:** Beim Scan entdeckte OpenRouter-Modelle via `pi.registerProvider('openrouter', {models: [...]})` registrieren (analog zur Ollama-Registration in `registerGroupModels`), so dass `modelRegistry.find('openrouter', id)` sie findet.
- **Aufwand:** ~1-2 Tage (Registration + Tests + sicherstellen dass keine Doppel-Registration mit anderen Extensions).

### Thread C — claude-sonnet-5 Dominanz (Teil von B)
- **Problem:** User beobachtet seit Tagen ausschließliches Routing auf `pi-claude/claude-sonnet-5`, selbst für simple Aufgaben.
- **Ursache:** Wenn die Free-Modelle (Thread B) nicht verfügbar sind weil nicht registriert, fällt die Kaskade immer auf den nächsten verfügbaren — das ist `pi-claude/claude-sonnet-5` (claude-bridge). Das ist ein **Symptom von B**, nicht ein separates Bug.
- **Fix:** Wird mit Thread B gelöst — sobald Free-Modelle registriert sind und `tryStream` sie findet, wird die Gruppen-Kaskade sie auch nutzen.
- **Aufwand:** 0 (in B enthalten).
